Exploratory research · Proposal / 06 Nov 2026

The hot hand of a language model.

Some AI sessions seem to get on a roll. One answer lands, the next is sharper, and suddenly the whole collaboration works. Is that a coincidence—or can earlier exchanges actually change the odds?

This is an open question, not a claim of discovery. KASKADE is proposing a controlled study of statistical streaks, context, and human–AI adaptation.

Evidence boundary

An 80-trial balanced assignment has been prepared and checked with synthetic, random outcomes only. Those outcomes are a software preflight, not evidence of model performance.

The hypothesis

Three explanations.
One familiar feeling.

Successive AI responses share a changing context, unlike independent roulette spins. But context dependence alone does not demonstrate a self-reinforcing performance effect.

H0 / CHANCE

A random winning streak.

Runs of success occur even when each attempt has fixed odds. Selection bias and task difficulty can make some sessions look special.

MEASURE · EXCESS SERIAL DEPENDENCE?
H1 / CONTEXT

Useful history changes the next step.

Validated successes may leave good instructions, representations, examples or corrections in context that help on a later task.

MEASURE · SUCCESS VS NEUTRAL HISTORY
H2 / HUMAN ADAPTATION

The collaborator finds a groove.

The human learns what to ask, when to correct, and which direction to pursue. The improvement may belong to the coupled system.

MEASURE · FIXED VS ADAPTIVE FEEDBACK

Phase I · Proposed method

Four starting conditions.

Repeat the same predefined tasks in fresh sessions with the same model configuration. Score actual outputs independently, not by what the assistant claims to have finished.

A

Cold start

The task begins without any warm-up exchange.

B

Neutral context

Preceding conversation, but no recorded success or failure.

C

Successful context

A separately checked successful warm-up precedes the task.

D

Unsuccessful context

A documented unsuccessful attempt precedes the task.

Prototype feasibility design: 20 trials per condition, balanced across task families. Primary comparison: C versus B. Sample size, warm-up equivalence, answer leakage, model version, and analysis must be resolved before a confirmatory study.

Interactive demonstration · Statistics, not AI

A winning streak can appear from nothing.

Try a fair coin flipped 20 times. You may get several wins in a row, although one flip does not improve the odds of the next.

This little exhibit makes the central problem visible: a streak by itself does not establish that a model has become more capable.

None of the flips are GPT or Claude trials.

PROPOSAL DOCUMENTED

02 / IMPLEMENTED PREFLIGHT

Offline control run

A repeatable design builds 80 planned trial assignments and analyzes synthetic null outcomes. This checks software plumbing only.

SYNTHETIC, NOT AI DATA

03 / NOT RUN

Actual model replication

Independent model calls, pinned configuration, externally graded answers and complete provenance are required to test the hypothesis.

NO EMPIRICAL RESULTS

How we would know

Proof over performance theater.

A model saying “done” is not success. A reproducible test, independently checked answer, or inspected working deliverable is. The future target is not merely capability, but reliability and recoverability.

No statement here suggests that KASKADE has proven a hot-hand effect, improved a deployed agent, or verified any neural mechanism. The private pilot workspace is not publicly mirrored.

“The model may be the same.
The path through the conversation is not.”
